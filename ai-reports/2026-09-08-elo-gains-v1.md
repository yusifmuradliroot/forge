# ELO gains — re-analysis, researched solutions, build plan
Date: 2026-09-08 | base: 2.9.0 (58/100, final-elo-2.9.0) | v1
Goal: raise the score WITHOUT leaving the league (offline, zero deps,
sub-second builds, single-digit-ms runtime, mobile-safe, minimalism).

## 1. Re-analysis: what 2.9.0 still leaks (verified by reading, not guessing)
- **G1 crypt key is static.** `crypt.py` hardcodes `^0x5A` in STUB and
  `_xor_hex`. The 2.9.0 salt feeds pack's XOR/shuffle only. So the string
  layer — the layer analysts actually read — is byte-identical across every
  file ever forged. Deep-audit C2 ("no per-file keys") is HALF-fixed.
- **G2 short names are order-stable.** `sorted(candidates)` + sequential
  `a..z`: same input yields same renames forever. Pattern stability helps
  the analyst; j-obfuscator's `mangled-shuffled` + `seed` exists for this.
- **G3 short strings are plaintext.** crypt skips values <12 chars: markers,
  keys, but ALSO real content (`"join"`, `"room:"`, URLs). A file with only
  short strings forges to near-plaintext.
- **G4 workflow points left on the floor.** No CI (deep-audit L13, still
  open), `PASSES.md` order line omits num/simp (stale since 2.9.0), no
  Windows story, error quality untested beyond happy paths.
- **G5 tamper stays thin by design.** Accident-sig + silent null + debugger
  gate. No self-check possible without self-read (elo-roadmap: dropped with
  cause). Nothing cheap here that is not theater.

## 2. Researched solutions (sources: live web, 2026-09-08)
- **j-obfuscator LOW preset** (the 75-point rival): selfDefending ON, string
  array rotate+shuffle+indexShift ON, wrappersCount 1, simplify ON,
  disableConsoleOutput ON, controlFlow OFF. Lesson: LOW buys its lead with
  string-layer variance + tripwire, NOT control flow. Both halves are
  borrowable in cheap form.
- **j-obfuscator `seed` + `identifierNamesGenerator: mangled-shuffled`**:
  seeded variance, diffable-by-default. Direct precedent for G2 fix.
- **numbersToExpressions** (`1234` -> `-0xd93+-0x10b4+...`): buys little per
  byte on our small files; our hex-only `num` already takes the cheap half.
  Extension = bloat for ~0 ELO. SKIP.
- **veil / kusoidev lightweight-VM** (61-point rival): VM-string decode
  without native primitives (no `String.fromCharCode`), per-build opcodes,
  opaque predicates wired into real paths, hot-path skipping. Borrowable
  idea: decode-stub variance per build (our G1 fix is the minimal form).
  Full VM = league exit (perf + size). NOT queued.
- **EntropyJS / ByteHide Shield docs**: server-keyed decryption (512-bit key
  never in bundle), self-mutating code, managed RASP. All require a server
  or a platform — league exit. NOT queued. Their honest line ("obfuscation
  buys attacker-hours, never secrecy") matches our LIMITS.md.
- **domainLockJS / j-obf domainLock**: ~2 lines + allow-list. Owner already
  declined for forge core (developer choice, league-gaps decision). CLOSED,
  not re-queued. Scoreboard zero stands.
- **HMAC authenticity**: public runner = public key = theater (decided).
  CLOSED. Scoreboard honesty kept instead.

## 3. Verdicts: QUEUED NOW (2.10.0) vs LATER vs NEVER
QUEUED NOW (all representation-only, battery-covered, default-stable):
- **Q1 crypt per-build key (fixes G1).** XOR base derives from FORGE_SEED
  (pack's `_salt_for` mechanism, shared helper); default (no env) = 0x5A,
  so default builds stay diffable and legacy `.fs` keep running (the stub
  carries its own key literal per file). Predicted: strings 8 -> 10.
- **Q2 short seed-shuffled assignment (fixes G2).** With FORGE_SEED set,
  candidate order shuffles before `a..z` assignment; default order
  unchanged. Predicted: names 10 -> 11.
- **Q3 `uni` pass (fixes G3).** Short printable-ASCII strings crypt skips
  become `\xNN` escapes (same value, no intent words). Same skip-set as
  crypt (markers, directives, object-key position, templates). Disjoint
  from crypt by length, either order safe; placed simp -> uni -> crypt.
  Predicted: strings 10 -> 11 (with Q1).
- **Q4 workflow round (fixes G4).** GitHub CI (check + runner battery +
  e2e), PASSES.md order + contract sweep, README pipeline line, error-path
  probes in selftest. Predicted: workflow 7 -> 10.
NEVER (decided, with cause): control-flow flattening, VM bytecode,
dead-code injection, debugProtection intervals, HMAC, domainLock in core.
LATER (trigger-based, unchanged): FS:3 chunked execution, cross-file
identifier cache (needs invalidation story first).
Predicted total: **58 -> ~65** (names +1, strings +3, workflow +3, tamper
and locks unchanged by principle). Veil (61) passed; j-obf LOW (75) still
leads on control flow — honestly out of our league-by-design.

## 4. Build plan (one commit, version 2.10.0)
1. shared `_seed.py`: FNV + seed-bytes from FORGE_SEED (pack + crypt +
   short import it; single source, no triple reimplementation).
2. crypt: `_key()` + stub embeds key literal (`^0x%02X`); default 0x5A.
3. short: shuffle candidate order under seed; default path identical.
4. uni: new pass, DEFAULT nolog,strip,short,num,simp,uni,crypt,pack.
5. check.py: FNV vector via shared helper; passes auto-covered; README +
   CHANGELOG + PASSES + QUICKSTART sweep in the same commit.
6. CI yml + selftest error-path probes.
7. Verify: selftest GREEN, full chain on biggest real-shape fixture,
   `node --check`, seeded-vs-default diff check, legacy `.fs` still runs.
