## Build time (real files, full chain)
| file | raw | .fs | total |
|---|---|---|---|
| omni.js (34 KB) | 33.9 KB | 48.2 KB | 118 ms |
| room_scout (46 KB) | 45.6 KB | 64.2 KB | 153 ms |
| voyager (6 KB) | 6.2 KB | 8.8 KB | 17 ms |

Slowest pass everywhere: **short** (tokenizer + multi-scan), then crypt.
Per-pass split (room_scout): nolog 23 / strip 14 / short 60 / crypt 33 / pack 22 ms.

## Size chain (room_scout, bytes)
raw 45592 → nolog 45287 (-1%) → strip 43237 (-5%) → short 41186 (-10% cum) →
crypt 48083 (+17% for the stub + hex) → .fs 64158 (1.41x raw, base64 tax).
Rule of thumb: `.fs ≈ 1.4 × raw`. Short only earns ~5-10% on already-tight
hand-written code (fewer single-decl locals than it hopes for).

## Pack scaling (synthetic, linear confirmed)
10 KB → 6 ms · 50 KB → 27 ms · 100 KB → 47 ms · 500 KB → 231 ms · 1 MB → 461 ms.
≈ 0.5 ms/KB. No cliffs to 1 MB.

## Runner decrypt (node, avg of 20)
omni.fs 49 KB → 2.7 ms · room_scout 63 KB → 1.1 ms · ws_core 16 KB → 0.5 ms.
Startup cost is noise next to one network round-trip. Browser TextDecoder/
atob path is the same order (unmeasured — needs a real room timing).

## Hot spots & what NOT to touch
- short's tokenizer dominates build time; poison adds one linear pre-scan
  each (measured inside the 60 ms). Fine as is.
- nolog `_line_of` is O(n) per strip (0.02 s / 500 logs) — fine.
- crypt hex-doubles long strings; MIN_LEN=12 keeps the tax bounded.
- Memory: whole-file strings ×~4 copies peak (~250 KB for our biggest file).
  Irrelevant at these sizes; revisit past 5 MB inputs.

## Verdict
Builds are sub-second, artifacts ~1.4x, runtime decrypt single-digit ms.
No perf work justified. Next perf look only if: inputs >1 MB, or mobile
room boot feels the runner (measure first).
